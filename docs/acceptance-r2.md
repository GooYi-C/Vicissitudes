## 门 3 · 环出口判据：免 API 自证（`r2-loop.spec.ts` 6 项全绿）

- **处境入队可见**：12 月过月，≥8 个月份有处境卡（SKL 门 2 延续——零 LLM 调用下玩家开始「遇到事」）；
- **了结走结算管道**：入队 → 点选 → TurnRunner 原子提交 → 出队 + 台账入档 → **陈旧引用重放被拒**（B-09-2）；
- **记忆三源写入**：大事件结算 → engine 保底 item 入档（importance 7）；管家维护跑月后**事实不灭**（content 逐字不变）；
- **目标池常驻**：每月 ≤3 条、exhausted 剔除生效；
- **两次运行逐位一致**（ARC-5 月级）；
- **selector 读通道**：处境卡数据可见（U-03——面板面数据源就位）。

## 施工期裁决留痕（四条）

1. **pendingSituations.queue 从数组改 record**（键 = situation key）：B-09-2「ResolveRef 精确命中」+ §7.4d 去重 key 单通道在结构上要求 key 寻址；出队 = 精确 remove 而非脆弱的数组下标。
2. **compiler 去掉 situation key 的 URL 编码**：'#' 是合法 record 键；编入/出队两侧同口径直接寻址（编码版会在手植队列与编译产物间产生键位漂移——首版实测暴露）。
3. **到期窗 EXPIRY_MONTHS = 2**：tick 提交后日期已进 M+1，玩家实际可动窗口 = 入队月的次月整月；1 月版会令所有处境在可见瞬间过期（首版实测暴露）。LL-05「不点即过期」语义不变。
4. **career 域随 R2 落树**（money/reputation/health，E-0.2 量纲）：事件效果 modifyPlayer 的落点——原计划 R4，但处境结算离了它整批否决，属 R2 的硬前置。goals 达标判定与奖励发放（career 接线面）留下一环。
