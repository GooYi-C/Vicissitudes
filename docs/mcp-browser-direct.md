# VS-01 浏览器纯直连改造（2026-09-18）

## 裁决与边界

用户要求模型调用走玩家直连、减少本项目 CF 流量，并以本轮“继续”确认执行。CF Pages 仅提供页面/JS/静态数据；生成和模型列表直达玩家配置的 HTTPS 服务商，**无自动 CF/第三方兜底**。本轮未执行 commit、push、部署或真实模型调用；线上旧发布不会被本地改动自动替换。**直连代码和 L2 验证已完成，真实服务商 L3 未测。**

- 保留此前 usage 实测/未测分离、脱敏观测、SSE 分片/中断、规则降级和本机存档。
- 云端 URL 不接受相对路径、userinfo、查询/片段、字面 IP/本机内网形状及本应用 origin。只做形状校验，不做浏览器 DNS/IP 锁定承诺。
- 使用 cors/omit/error/no-referrer；Bearer key 只发给玩家选定服务商，不放 URL/body、prompt、存档/导出/日志。不自动为 CORS 错误重试，不用 no-cors 绕过。
- 模型列表仅手动点击读取；开局/刷新零自动探测。列表失败可手填，列表不计生成调用数。
- 旧5个 CF 文件及对应60项历史测试完整移到 tests/fixtures/cf-proxy 和 tests/unit/archived-proxy。历史通过不代表生产安全通过，见 docs/mcp-cf-proxy-archive.md。
- 新纯静态部署门拦住 functions/、_worker.js 和旧 API 重定向/源码回退；build后和deploy前强制验证。新增 L1 apiEndpoint.ts 只多一条 L6→L1 依赖，不加依赖包/层间豁免。
- 断言 LLM-37～LLM-41 新增生产口径（最后一条为浏览器发现的落档时序补账）；此前182条断言不删不改，代理相关条目在本版本转为历史证据，不能算现网代理能力。

## 当前操作方式

1. 玩家在本机设置页填 baseUrl（含服务商实际版本前缀，如 https://api.example.com/v1）、model、自己的 key；也支持完整 chat/completions URL。不会猜补版本。
2. 可手动点“读取模型列表（直连）”。服务商须允许应用页面 Origin、Authorization/Content-Type 预检和请求方法；OpenAI兼容不自动代表CORS兼容。
3. 端点支持时再手动打开usage开关。缺失的token/缓存量/价格仍标未测，不拿字符或模板hash冒充真实账单。
4. 失败只给安全的分类提示；网络/CORS/DNS/TLS无法精确区分。玩家可主动更换服务商或明确配置可信端点，但应用不暗中换代理。
5. 实际线上停用旧CF路由需要发布新的纯静态版本；本轮不自动发布。静态页面仍有CF加载流量，减少的是模型中转/Functions流量，不是服务商模型费用。

## 浏览器发现与修复：保存完成屏障（LLM-41）

首次纯虚拟时钟冒烟遇到 IndexedDB 等待超时，测试改用本地真实时钟等待后，复现了业务时序缺口：页面已到1922-07，刷新却读回1922-02。App 原先用 void persist()，UI推进没有等存档事务完成。

修复：开局、免API过月和模型回合都等待 writeSave 的事务完成才解除动作锁；保存中/成功/失败有可见状态，失败不回显原始错误。新增3项UI测试覆盖慢写入/重复操作、开局未保存不得调用模型、失败可见且不泄漏。游戏引擎公式、存档schema和VS-02日结范围均未改变。
